# Simplify: 代码审查与清理

审查所有变更文件的代码复用、质量和效率问题，发现并直接修复。

## Phase 1: 识别变更

运行 `git diff`（或 `git diff HEAD` 如有暂存变更）查看变更内容。
如果没有 git 变更，审查用户提到的或本次会话中最近修改的文件。

## Phase 2: 三路并行审查

依次执行以下三个审查维度，每个维度都要覆盖全部变更：

### 审查 1: 代码复用 (Code Reuse)

对每处变更：

1. **搜索已有工具函数和辅助方法**，看是否有可替代新写代码的。在整个代码库中查找相似模式——重点关注 utils 目录、共享模块和相邻文件。
2. **标记重复已有功能的新函数。** 建议改用已有函数。
3. **标记可用已有工具替代的内联逻辑** —— 手写字符串处理、手动路径处理、自定义环境检查、临时类型守卫等。

### 审查 2: 代码质量 (Code Quality)

审查以下代码质量问题：

1. **冗余状态**: 重复已有状态的 state、可从其他值派生的缓存、可改为直接调用的观察者/副作用
2. **参数蔓延**: 不断给函数加新参数，而非重构或重新组织
3. **复制粘贴变体**: 近似重复的代码块，应抽象为共享实现
4. **泄漏抽象**: 暴露了本应封装的内部细节，或破坏了已有抽象边界
5. **字符串硬编码**: 在已有常量、枚举或类型联合的地方使用裸字符串
6. **不必要的嵌套**: 无布局价值的包装元素/组件
7. **不必要的注释**: 解释"是什么"的注释（好的命名已做到）、叙述变更的注释、引用任务编号的注释——删除；只保留"为什么"的注释（隐藏约束、微妙不变量、workaround）

### 审查 3: 效率 (Efficiency)

审查以下效率问题：

1. **不必要的计算**: 冗余计算、重复文件读取、重复网络/API 调用、N+1 模式
2. **缺失并发**: 顺序执行的独立操作，本可并行
3. **热路径膨胀**: 在启动或请求/渲染热路径上新增阻塞操作
4. **无操作更新**: 轮询循环或事件处理器中无条件的状态更新——添加变更检测守卫
5. **不必要的存在检查**: 先检查文件/资源是否存在再操作（TOCTOU 反模式）——直接操作并处理错误
6. **内存问题**: 无界数据结构、缺失清理、事件监听器泄漏
7. **过于宽泛的操作**: 只需部分内容时读取整个文件，只需一项时加载全部

## Phase 3: 修复问题

汇总三个审查维度的发现，逐一直接修复。
如果是误报或不值得修复，记录并跳过——不争论，直接继续。

完成后，简要总结修复了什么（或确认代码已经很干净）。
