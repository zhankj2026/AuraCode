# Skillify: 会话过程捕获为可复用 Skill

将当前会话中执行的可重复过程分析并捕获，生成标准化的 SKILL.md 文件供未来复用。

## 目标

将当前会话的工作流程转化为结构化、可复用的 Skill，包含清晰的步骤、成功标准和触发条件。

## 执行流程

### Step 1: 分析会话历史

回顾当前会话的消息记录，识别：
- 执行了什么可重复的过程
- 输入参数是什么
- 按顺序执行的各个步骤
- 每个步骤的成功标准/产出物
- 用户在哪些地方进行了纠正或调整
- 使用了哪些工具和权限

```bash
# 查看 git diff 了解本次变更范围
git diff --stat HEAD
git log --oneline -5
```

**成功标准**: 能够清晰描述出完整的流程步骤和每个步骤的目的。

### Step 2: 与用户确认

使用 `ask_user` 工具向用户确认：

**第一轮: 高层确认**
- 建议 Skill 名称和描述
- 确认高层目标和成功标准

**第二轮: 细节确认**
- 展示识别出的步骤列表
- 确认参数（是否需要输入参数，参数格式）
- 确认保存位置：
  - **项目级** (`.auracode/skills/<name>/SKILL.md`) — 仅当前项目使用
  - **用户级** (`~/.auracode/skills/<name>/SKILL.md`) — 跨所有项目

**第三轮: 触发条件**
- 确认何时应该自动调用此 Skill
- 建议触发短语

**成功标准**: 用户对名称、步骤、参数和保存位置均确认。

### Step 3: 生成 SKILL.md

使用以下标准格式创建 SKILL.md：

```markdown
---
name: {{skill-name}}
description: {{一行描述}}
trigger: {{用户手动触发的描述}}
when_to_use: {{模型自动触发的条件，包含触发短语示例}}
argument-hint: "{{参数提示}}"
arguments:
  - {{参数1名}}
  - {{参数2名}}
---

# {{Skill 标题}}

描述此 Skill 的目的和使用场景。

## 输入参数
- `$1`: {{参数1描述}}
- `$2`: {{参数2描述}}

## 目标
清晰定义此工作流程的目标和完成标准。

## 步骤

### 1. {{步骤名称}}
具体操作说明。包含需要执行的命令。

**成功标准**: 描述此步骤完成的标志。

### 2. {{步骤名称}}
...
```

**格式规范**:
- 每个步骤必须包含 **成功标准**
- `when_to_use` 以 "当..." 开头，包含触发短语示例
- `arguments` 只在确实需要参数时设置
- 步骤保持具体可操作，避免模糊描述

**成功标准**: 生成的 SKILL.md 符合上述格式规范，frontmatter 语法正确。

### Step 4: 保存并确认

将 SKILL.md 写入用户选择的目录，然后告知：
- 文件保存路径
- 调用方式: `/skillify` 或 `/skills activate {{name}}`
- 可以直接编辑 SKILL.md 来完善

**成功标准**: 文件成功写入，`/skills list` 能看到新 Skill。

## 注意事项

1. **不要过度询问** — 简单流程不需要太多轮确认
2. **关注用户纠正** — 用户在会话中纠正你的地方，往往是最重要的 Skill 规则
3. **保持实用** — 生成的 Skill 应该是真正可复用的，而非过度泛化
4. **先展示后保存** — 写入文件前让用户预览完整内容
